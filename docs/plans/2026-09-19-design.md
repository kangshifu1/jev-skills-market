# Jev Skills Market — initial design

## Product decision

Build a repository-distributed assistant and skill catalog first. Compared with a
link directory it provides executable adapters and validation. Compared with a full
desktop application it keeps speech vendors, browser drivers and model providers replaceable.
Repository name: `jev-skills-market`. Publisher: the authenticated user's GitHub account.
Independent community branding, not an official TypeSafe distribution.

## Components

- One installable Codex plugin containing five bundled skills, plus an external catalog entry.
- First import: independent `kangshifu1/jev-computer-use` repository, based on a pinned MIT Jev Browser Use engine.
- External computer-use repository owns both the Codex tab and isolated Playwright Chrome/Chromium backends. No market dependency.
- Assistant catalog router: preview request offline; optionally ask Jev for a typed
  recommendation; never execute a recommendation automatically.
- Automation-test skill: explicit assertions and evidence, with pass/fail/not-covered.
- Finance-research skill: sourced research and local deterministic performance metrics;
  no live broker adapter or prediction claims.
- Voice-assistant skill: provider-neutral architecture and executable cancellable
  turn state machine; audio transcription, conversational LLM and TTS remain external adapters.
- TypeSafe's original development guidance with its license.

## Data and execution

Task -> catalog or conversation -> bounded Jev judgment -> host permission check ->
browser action -> fresh state -> deterministic assertions -> host explanation.
Keys are loaded locally; only the configured model endpoint receives task/page data.
An origin allowlist bounds top-level navigation; it is not network isolation. Third-party
page resources may load. Page text can be adversarial; it does not expand the task contract.

## Verification and release

1. Preserve source files, commit identifiers, licenses and file hashes.
2. Validate catalog, install paths, manifest, skill frontmatter and local references.
3. Exercise router invalid-response rejection, assertion outcomes, financial math,
   voice cancellation and stale-result rejection.
4. Run a real local browser with mocked Jev responses. Verify actual DOM effects,
   origin blocking, duplicate controls, and independent result checks.
5. Test skill discovery and plugin package shape, scan the staged files, create a
   public GitHub repository and publish v0.1.0 with explicit verification limitations.

## Initial limits

This is a developer preview, not a complete desktop chat client. Browser support is
top-level standard HTML controls; frames, canvas, file uploads and native applications
need host intervention or a future adapter. Voice is a tested control contract, not
a connected microphone service. Live model quality requires a configured API key and
representative user tasks; offline tests do not establish it.
