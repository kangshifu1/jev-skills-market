## 使用范围与版本

- Laya 的主基准仍引用第三方 Jev 成绩；本轮另行核实中文社区诊断 `research/benchmarks/feishu_zh/run.py` 的真实 TypeSafe 调用，按该评价入口收录，保留历史排除记录。
- JevForge 对照脚本要求明确配置决策端点与凭据，模型标识为 `~typesafe/jev-latest`。没有默认端点，不编造提供商配置或免配置命令。
- gbrain-evals 通过 `--gbrain <checkout>@<ref>` 使用独立 System One 运行时。已读取报告固定的 [gbrain 9196543d](https://github.com/garrytan/gbrain/tree/9196543dffd8c6b918b232559956f4693874e67b) 的 TypeSafe 请求配置与执行代码；这不是 gbrain 默认主分支的能力承诺。重算已存结果与实时调用分别处理。
- jevmem 按 CLI／插件整体登记；未运行 hook、读取聊天或修改记忆。
- jevals 和 NestJS 集成只核实请求实现；未验证上游成本、速度、轨迹评价或防护准确率。
- Engraphis 的直接 TypeSafe 路径需要显式 BYOK 和逐次远程同意，默认本地模式及托管代理模式不混同；附带 MCP Skill 不代表已连接运行时。
- Creator Lab 需要独立采集、转写与分类提供商；上游展示为保存分析回放，本轮未采集社交数据或复现结果。
- Active Harness 使用 Vercel 的 TypeSafe 兼容入口，返回类型化答案，不是聊天生成或 token 流式接口。
